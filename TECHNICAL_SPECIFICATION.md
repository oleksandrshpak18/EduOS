# ТЕХНІЧНА СПЕЦИФІКАЦІЯ ПРОЄКТУ (TECHNICAL SPECIFICATION)
## Інтерактивна навчальна віртуальна операційна система «EduOS»

**Версія документа:** 1.0  
**Базовий документ вимог:** Технічне завдання v2.0  
**Цільова платформа:** GitHub Pages (Static Client-Side Web Application, PWA-ready)

## 1. Загальний огляд та архітектурні принципи

### 1.1. Призначення системи
«EduOS» — це повнофункціональний автономний вебтренажер, що імітує роботу настільної операційної системи (десктоп, вікна, файлова система, утиліти, термінали) та призначений для формування практичних навичок з інформатики в учнів 5–11 класів. Проєкт функціонує виключно у браузері користувача без використання бекенду, бази даних чи серверної авторизації.

### 1.2. Архітектурний шаблон (Architectural Pattern)
Проєкт базується на **модульній подійно-орієнтованій архітектурі (Modular Event-Driven Architecture)** з використанням патернів:
- **Central EventBus (Mediator)**: забезпечення слабкого зв'язку (loose coupling) між ядром, файловою системою, менеджером вікон та додатками.
- **Service-Oriented Core**: ядро системи надає сервіси (`StorageService`, `VFSService`, `WindowManagerService`, `ProfileService`, `AuditLogService`).
- **Component Application Contract**: кожна програма є ізольованим класом/модулем, що реалізує стандартизований життєвий цикл (`init`, `render`, `destroy`, `saveState`, `restoreState`).

## 2. Модель даних та сховище (Data Storage & VFS)

### 2.1. Сховище IndexedDB («EduOS_DB»)
Використовується нативна клієнтська база даних IndexedDB версії 1.
Таблиці (Object Stores):
1. `profiles`:
   - Ключ: `profileId` (string, наприклад: `Petrenko_Andriy_6-A`).
   - Поля: `{ profileId, lastName, firstName, gradeClass, createdAt, lastLoginAt, settings }`.
2. `vfs_nodes`:
   - Ключ: `id` (string, UUID).
   - Індекси: `by_profileId` (`profileId`), `by_parentId` (`[profileId, parentId]`), `by_path` (`[profileId, path]`).
3. `learning_progress`:
   - Ключ: `id` (string: `${profileId}_${packageId}`).
   - Поля: `{ profileId, packageId, status, score, maxScore, completedTasks: [], startedAt, finishedAt }`.
4. `audit_logs`:
   - Ключ: `id` (auto-increment integer).
   - Індекси: `by_profile` (`profileId`), `by_timestamp` (`timestamp`).
   - Фіксація дій учня: копіювання, переміщення, створення, видалення, виконання команд.

### 2.2. Специфікація вузла файлової системи (VFS Node Specification)
Кожен файл, папка, диск та системний об'єкт є вузлом `VFSNode`:

```typescript
interface VFSNode {
  id: string;                     // Унікальний UUID v4
  profileId: string;              // Ідентифікатор профілю учня
  parentId: string | null;        // ID батьківського вузла (null для кореневих дисків)
  name: string;                   // Назва з розширенням (наприклад, "document.txt")
  type: 'drive' | 'directory' | 'file' | 'shortcut' | 'trash_item';
  extension: string;              // "txt", "png", "zip", "json", "lnk" тощо (порожньо для директорій)
  size: number;                   // Розмір у байтах
  createdAt: number;              // Timestamp створення
  updatedAt: number;              // Timestamp останньої зміни
  attributes: {
    readonly: boolean;            // Атрибут "Лише для читання"
    hidden: boolean;              // Атрибут "Прихований"
    system: boolean;              // Системний файл (захищений від випадкового видалення)
  };
  permissions: {
    owner: string;                // Власник ("student", "system", "admin")
    r: boolean;                   // Читання
    w: boolean;                   // Запис
    x: boolean;                   // Виконання
  };
  content: string | ArrayBuffer | null; // Вміст файлу (UTF-8 текст, DataURL, або ArrayBuffer)
  metadata?: {
    originalPath?: string;        // Для елементів у Кошику (для відновлення)
    targetPath?: string;          // Для ярликів (.lnk)
    icon?: string;                // Кастомна іконка
    contentType?: string;         // MIME-тип (image/png, text/plain)
  };
}
```

### 2.3. Топологія віртуальних дисків
- `C:` — Системний диск:
  - `C:\Користувачі\Учень\` (`Документи`, `Зображення`, `Музика`, `Відео`, `Завантаження`, `Робочий стіл`).
  - `C:\Windows\System32\` (віртуальні системні бінарники).
- `D:` — Навчальний диск:
  - `D:\Інформатика\`
  - `D:\Практичні роботи\`
  - `D:\Проєкти\`
- `Мережа` (віртуальний диск `NET:` або `\\LAB-SERVER\`):
  - `\\LAB-SERVER\Загальні_файли\`
  - `\\LAB-SERVER\Підручники\`
- `Кошик` (`RECYCLE_BIN:`):
  - Спеціальний ізольований системний розділ. Видалені файли переміщуються сюди зі збереженням `originalPath`.

## 3. Специфікація системних API

### 3.1. Віртуальна файлова система (`VFSService`)
Клас `VFSService` інкапсулює роботу з IndexedDB та надає асинхронні методи з перевіркою прав доступу та генерацією подій:

| Метод | Сигнатура | Призначення |
|---|---|---|
| `resolvePath` | `resolvePath(path: string): Promise<VFSNode \| null>` | Перетворення відносного або абсолютного шляху (Windows-стиль `C:\...` або Unix-стиль `/c/...`) у вузол |
| `listDir` | `listDir(dirIdOrPath: string): Promise<VFSNode[]>` | Отримання списку дочірніх вузлів |
| `createFile` | `createFile(parentPath: string, name: string, content?: any, attrs?: Partial<Attributes>): Promise<VFSNode>` | Створення нового файлу |
| `createDirectory` | `createDirectory(parentPath: string, name: string): Promise<VFSNode>` | Створення папки |
| `readFile` | `readFile(path: string, encoding?: 'text' \| 'binary'): Promise<string \| ArrayBuffer>` | Читання вмісту |
| `writeFile` | `writeFile(path: string, content: any): Promise<void>` | Запис у файл (з перевіркою `readonly`) |
| `deleteNode` | `deleteNode(path: string, permanent?: boolean): Promise<void>` | Переміщення у кошик або безповоротне видалення |
| `restoreFromTrash` | `restoreFromTrash(trashNodeId: string): Promise<void>` | Відновлення об'єкта в `originalPath` |
| `emptyTrash` | `emptyTrash(): Promise<void>` | Остаточне очищення кошика |
| `copyNode` | `copyNode(srcPath: string, destDirPath: string, newName?: string): Promise<VFSNode>` | Копіювання з рекурсією для папок |
| `moveNode` | `moveNode(srcPath: string, destDirPath: string, newName?: string): Promise<VFSNode>` | Переміщення вузла |
| `renameNode` | `renameNode(path: string, newName: string): Promise<VFSNode>` | Перейменування вузла |
| `setAttributes` | `setAttributes(path: string, attrs: Partial<Attributes>): Promise<void>` | Зміна атрибутів (прихований, лише читання) |
| `search` | `search(startPath: string, query: string, options?: SearchOptions): Promise<VFSNode[]>` | Рекурсивний пошук за маскою/назвою |

Кожна модифікаційна дія автоматично:
1. Записується в `AuditLogService` (`action`, `path`, `timestamp`, `details`).
2. Емітує подію через `EventBus.emit('vfs:changed', { action, targetNode })`.

### 3.2. Менеджер вікон (`WindowManagerService`)
Відповідає за маніпуляції вікнами у DOM:
```typescript
interface WindowOptions {
  appId: string;
  title: string;
  icon: string;
  width?: number;
  height?: number;
  minWidth?: number;
  minHeight?: number;
  isResizable?: boolean;
  isModal?: boolean;
  initialState?: 'normal' | 'maximized' | 'minimized';
  params?: Record<string, any>;
}
```
**Функціональні механізми WMS:**
- **Boundary Clamping**: запобігання втраті вікна за межами екрана при зміні розміру браузера (`window.onresize`). Вікно не може мати координату `y < 0` або бути повністю зміщеним за межі десктопа.
- **Z-Index Layering**: активне вікно отримує найвищий `z-index`. Модальні діалоги блокують взаємодію з батьківським вікном.
- **State Restoration**: збереження позиції та розміру вікон під час згортання/розгортання.
- **Taskbar Synchronization**: створення кнопок запущених програм, відображення стану активності, згортання/розгортання в один клік.

## 4. Специфікація вбудованих прикладних програм

### 4.1. Провідник (Explorer)
- **Інтерфейс**: Триярусний (меню дій/тулбар -> адресний рядок і пошук -> робоча область із деревом папок зліва та вмістом справа).
- **Режими відображення**:
  1. `large-icons` (сітка великих значків 64x64);
  2. `medium-icons` (значки 48x48);
  3. `small-icons` (значки 24x24);
  4. `list` (компактний список);
  5. `details` (таблиця: Ім'я, Дата зміни, Тип, Розмір, Атрибути).
- **Сортування**: За будь-яким стовпцем за зростанням/спаданням.
- **Адресний рядок**: Підтримка інтерактивного введення шляху з автодоповненням та «хлібних крихт» (breadcrumbs).
- **Імпорт/Експорт**:
  - Імпорт реальних файлів: використання HTML5 `<input type="file">` або Drag-and-Drop з робочого столу комп'ютера у вікно Провідника.
  - Експорт: формування Blob та ініціація клієнтського завантаження файлу на диск користувача.

### 4.2. Текстовий редактор (Notepad)
- **Можливості**:
  - Відкриття та редагування `.txt`, `.json`, `.csv`, `.log`, `.bat`, `.sh`.
  - Статусбар: позиція курсора (Рядок, Стовпчик), кодування (UTF-8), статус збереження (зірочка `*` при змінах).
  - Функція пошуку та заміни тексту.
  - Гарячі клавіші: `Ctrl+S` (зберегти), `Ctrl+O` (відкрити), `Ctrl+F` (пошук).

### 4.3. Графічний редактор (Paint)
- **Технологія**: HTML5 2D Canvas.
- **Інструменти**: Олівець, Пензель, Гумка, Лінія, Прямокутник, Еліпс/Коло, Заливка (алгоритм Flood Fill на масиві `ImageData`), Піпетка.
- **Палітра**: 16 базових кольорів + вибір кольору через HTML Color Picker.
- **Налаштування**: Товщина штриха (1px, 3px, 5px, 10px).
- **Історія змін**: Стек Undo/Redo на 15 станів.
- **Формати**: Збереження у віртуальну файлову систему як `.png` у вигляді Base64 Data URL.

### 4.4. Архіватор (Archiver)
- **Бібліотека**: `JSZip v3.x` (легковажна клієнтська бібліотека).
- **Функціональність ZIP**:
  - Створення архіву з обраних файлів/папок.
  - Перегляд дерева архіву без його видобування.
  - Додавання та вилучення файлів.
  - Повне або часткове розархівування у задану папку.
- **Функціональність 7Z / TAR.GZ**:
  - Навчальна імітація структури архіву та розпакування без використання важких WebAssembly модулів, щоб не перевантажувати вебдодаток і гарантувати сумісність із GitHub Pages.

### 4.5. Командний рядок (CMD) та Термінал Linux (Bash)
Два окремих термінальних емулятори, що транслюють команди в API `VFSService`:

Обидва термінали мають:
- Історію команд (клавіші `Стрілка вгору` / `Стрілка вниз`).
- Автодоповнення імен файлів клавішею `Tab`.
- Підтримку відносних та абсолютних шляхів.

### 4.6. Системні утиліти
1. **Панель налаштувань (Settings)**:
   - *Персоналізація*: вибір шпалер (вбудовані фото, кольори, завантаження власних), темна/світла тема, розмір значків робочого столу.
   - *Система*: інформація про версію ОС, віртуальний процесор, оперативну пам'ять.
   - *Сховище*: діаграма використання пам'яті IndexedDB, очищення кешу.
2. **Керування дисками (Disk Management)**:
   - Візуалізація дисків `C:`, `D:`.
   - Графік зайнятого / вільного простору.
   - Функція форматування навчального диска `D:` (скидання до початкового стану).
   - Зміна мітки тома.
3. **Диспетчер завдань (Task Manager)**:
   - Список запущених віконних процесів з можливістю примусового закриття.
   - Модельні графіки використання CPU та RAM із плавною анімацією.
4. **Мережеве оточення (Network Simulator)**:
   - Список віртуальних комп'ютерів у класі (`PC-01`, `PC-02`, `SERVER-SCHOOL`).
   - Моделювання мережевої папки для спільного обміну файлами.
   - Утиліта `ping` для перевірки з'єднання.
5. **Віртуальний браузер (Browser)**:
   - Навчальна пісочниця із вбудованими вебсторінками (Шкільна бібліотека, Вікіпедія-лайт з інформатики, пошуковик).
   - Імітація скачування файлів із навчальних сторінок у віртуальну папку `Завантаження`.

```json
          "path": "D:\\Практичні роботи\\Мої документи"
        }
      }
    },
    {
      "id": "step-2",
      "order": 2,
      "title": "Копіювання файлу",
      "instruction": "Скопіюйте файл 'Текст.txt' у створену папку 'Мої документи'.",
      "points": 3,
      "hint": "Виділіть файл 'Текст.txt', натисніть Ctrl+C, відкрийте папку 'Мої документи' та натисніть Ctrl+V.",
      "hintPenalty": 0.5,
      "validator": {
        "type": "file_exists",
        "params": {
          "path": "D:\\Практичні роботи\\Мої документи\\Текст.txt",
          "matchContent": true,
          "expectedContent": "Початковий текст завдання"
        }
      }
    }
  ]
}
```

### 5.2. Типи валідаторів (`ValidationEngine`)
Валідація здійснюється декларативно без використання небезпечного `eval()`:

1. `file_exists`: перевірка наявності файлу за вказаним шляхом. Додаткові параметри:
   - `matchContent` (bool): перевірка тексту;
   - `contentRegex` (string): перевірка вмісту за регулярним виразом;
   - `minSize` / `maxSize` (number): перевірка розміру.
2. `directory_exists`: перевірка існування папки.
3. `node_not_exists`: перевірка видалення файлу/папки.
4. `recycle_bin_contains`: перевірка, що об'єкт переміщено у кошик.
5. `attribute_check`: перевірка наявності атрибутів (`hidden === true`, `readonly === true`).
6. `archive_contains_file`: перевірка вмісту ZIP-архіву за вказаним шляхом.
7. `audit_action_sequence`: перевірка журналу дій учня (наприклад, що файл був саме скопійований через буфер/меню, а не створений наново).
8. `command_executed`: перевірка виконання конкретної команди в терміналі (наприклад, `mkdir TestFolder` або `dir /s`).
9. `setting_applied`: перевірка зміни фонового зображення або теми оформлення.

### 5.3. Модель оцінювання (`ScoringEngine`)
- **Навчальний режим**:
  - Спроби перевірки необмежені.
  - Підказки доступні, штраф за перегляд підказки віднімається від балів завдання (але оцінка не опускається нижче 0).
  - Миттєвий зворотний зв'язок із поясненням помилки.
- **Контрольний режим**:
  - Фіксований час на виконання (опціонально, з таймером).
  - Підказки заблоковані.
  - Штрафи за невдалі спроби перевірки (наприклад, -10% від вартості завдання за кожну хибну спробу).

### 5.4. Генератор персональних PDF-сертифікатів (`CertificateService`)
- Використовує бібліотеку `jsPDF`.
- **Шрифт**: Завантаження та вбудовування TTF-шрифту з підтримкою української кирилиці (Roboto або Open Sans) безпосередньо в бандл.
- **Оформлення**:
  - Формат: A4, альбомна орієнтація (Landscape, 297x210 мм).
  - Елементи: геометрична орнаментна рамка, навчальний логотип «EduOS», QR-код валідації (містить захешований рядок перевірки), водяний знак.
  - Текстові дані: Прізвище, Ім'я, Клас, Назва теми практичної роботи, Кількість набраних балів / Максимум, Відсоток успішності, Точна дата та час, Оцінка за 12-бальною системою.
- **Дії**: Попередній перегляд у модальному вікні, завантаження у форматі `.pdf`, друк через `window.print()`.

## 6. Конструктор завдань (Task Authoring Studio)

Окремий графічний застосунок у системі, що дозволяє вчителю створювати власні практичні роботи:
1. **Майстер налаштування пакета**:
   - Назва роботи, клас, навчальна тема, опис, максимальний бал, режим (навчальний/контрольний).
2. **Конструктор початкового стану (VFS Snapshot)**:
   - Візуальне додавання папок і файлів, які автоматично розгорнуться у віртуальній ОС учня при старті роботи.
3. **Редактор завдань**:
   - Додавання кроків завдання, інструкції, підказки, штрафних балів.
   - Вибір типу перевірки з випадаючого списку (без написання коду) та заповнення форми параметрів.
4. **Валідація та експорт**:
   - Перевірка валідності створеного JSON відповідно до схеми.
   - Експорт готового `.json` файлу для розміщення в репозиторії або завантаження учнем через кнопку «Імпортувати завдання».

## 7. Безпека, надійність та ізоляція (Security & Sandboxing)

1. **Ізоляція середовища**: Жодна віртуальна операція не має доступу до реальної файлової системи комп'ютера, крім стандартних браузерних діалогів завантаження/вивантаження.
2. **No-Eval політика**: Повна відмова від методів `eval()`, `new Function()`, `setTimeout(string)`. Усі правила перевірки завдань виконуються суто декларативними функціями валідатора.
3. **Захист від XSS**: Усі користувацькі назви файлів, вміст документів, прізвища учнів та виведення термінала обов'язково проходять санітизацію (`textContent` або утиліту екранування `escapeHtml`) перед рендерингом у DOM.
4. **Пам'ять та ресурси**:
   - Обмеження максимального розміру імпортованого файлу (до 15 МБ) для запобігання переповненню квоти IndexedDB браузера.
   - Обмеження буфера історії термінала (до 500 рядків) та стеку Undo в Paint.
5. **Офлайн-робота (PWA)**:
   - Наявність `sw.js` (Service Worker) зі стратегією `Cache-First` для статичних ресурсів додатку (HTML, CSS, JS, шрифти, іконки). Додаток працює в комп'ютерному класі навіть за відсутності інтернет-з'єднання після першого завантаження.
